# 설계

## 1. 역할 경계

| | 담당 | 하는 일 |
|---|---|---|
| **판단** | Claude (대화) | 웹 검색, 출처 교차 검증, 분야별 정리, 글 작성, 제목·태그 결정 |
| **실행** | MCP 서버 | 로그인 세션 관리, 에디터 조작, 이미지 업로드, 발행 |

이 경계를 지키는 이유:

- **MCP 안에 LLM 호출을 넣지 않는다.** 글 품질은 대화로 즉시 고칠 수 있어야 한다.
  프롬프트를 고쳐 재실행하는 방식은 반복 비용이 크다.
- MCP 는 "시키면 그대로 올리는" 결정적인 부품으로 남는다. 실패하면 원인이
  에디터 조작 하나로 좁혀진다.

## 2. 인터페이스: HTML

Claude → MCP 로 넘기는 것은 **완성된 HTML 한 덩어리**다.

```html
<h2>iOS 27 퍼블릭 베타 100 공개</h2>
<p>애플이 ...</p>
<img src="https://example.com/shot.png" alt="설정 화면">
<blockquote cite="https://apple.com/newsroom/...">애플 뉴스룸 원문</blockquote>
```

### 왜 HTML 을 그대로 붙여넣지 않는가

스마트에디터 ONE 에는 **HTML 소스 편집 모드가 없다.** 구버전(스마트에디터 2.0)
에 있던 기능이 ONE 에서 빠졌다. 따라서 HTML 을 에디터에 직접 주입할 방법이 없다.

클립보드로 HTML 을 붙여넣으면 에디터가 자체 블록으로 변환해 주긴 하지만:

- `<img src="외부URL">` 은 **본문에 들어가지 않는다.** 네이버는 자사 CDN 에
  업로드된 이미지만 본문에 넣는다. 이미지가 통째로 사라진다.
- 제목 스타일, 링크 카드 변환이 유실된다.
- 변환 결과를 코드가 통제할 수 없다.

그래서 **MCP 가 HTML 을 파싱해 블록으로 바꾼 뒤 에디터를 블록 단위로 조작한다.**
경계는 HTML 로 두되, 변환 부담은 MCP 가 진다.

### 지원 HTML 부분집합

파서는 화이트리스트 방식이다. 목록에 없는 태그는 텍스트만 남기고 버린다.

| 태그 | 처리 |
|---|---|
| `<h2>` `<h3>` | 소제목 (레벨 2/3) |
| `<p>` | 문단 |
| `<figure>` `<img>` `<figcaption>` | 이미지 + 출처 캡션. `src` 는 **로컬 절대 경로**를 기대한다 |
| `<blockquote cite>` | 인용 + 출처 링크 |
| `<ul>` `<ol>` `<li>` | 목록 |
| `<a href>` | 링크 (독립 줄이면 링크 카드로 자동 변환됨) |
| `<hr>` | 구분선 |
| `<strong>` `<em>` | 인라인 강조 |

**정보성 글이므로 출처 표기가 핵심이다.** `<blockquote cite>` 와 글 말미
출처 목록을 1급으로 다룬다.

## 3. 기존 코드 재사용

`Auto-CooPangPartners` 8,436줄 중 약 2,100줄만 가져온다.

### 그대로 가져오는 것

- `naver.py` — `NaverPublisher` (1,498줄). 이 프로젝트의 핵심.
  - 크롬 user-data-dir 재사용으로 로그인 세션 유지
  - `_has_session()` 은 `NID_SES` 쿠키만 확인하고 페이지 이동을 하지 않는다
    (이동하면 2단계 인증 입력 화면이 날아간다 — 실제 겪은 버그)
  - `_write_blocks()` 블록 렌더러, 이미지 업로드 3중 폴백
  - 블록마다 커서 위치 재확인 (이미지 삽입 후 포커스 유실 대응)
  - 카테고리·공개범위 선택, 진단 스크린샷 덤프
- `publisher.py` `errors.py` `retry.py` `paths.py` `credstore.py` `ratelimit.py`
- `config.py` 의 `NaverConfig`

### 버리는 것

`generator.py` `llm_providers.py` — Claude 가 대화에서 하므로 불필요.
`coupang.py` `toss.py` `social.py` `samples.py` `wordpress.py` — 쿠팡 전용.
`gui.py` `cli.py` `pipeline.py` `runner.py` `clipboard_ui.py` `theme.py` —
MCP 서버가 진입점이 되므로 UI/오케스트레이션 계층 불필요.

### 고쳐야 하는 것

1. **블록 스키마** — `product_index` 로 대상을 가리키는 구조를 버린다.
   `image` 는 URL/경로를 직접 받고, `product_link` 는 범용 `link` 가 되며,
   `quote`(출처 인용) 블록을 추가한다.
2. **`_insert_image`** — 지금은 `block.image_url` 다운로드 경로뿐이다.
   로컬 파일 경로도 받게 분기한다. `_upload_image_file()` 이 이미 경로를
   받으므로 다운로드 단계만 건너뛰면 된다.
3. **`_insert_link`** — `"▶ 상품 보러가기"` 하드코딩 제거.
4. **대가성 고지 강제 삽입** — `DISCLOSURE_TEXT` 를 첫 블록에 강제로 넣는
   로직 제거. 정보성 글에는 해당 없다. 말미 출처 섹션으로 대체한다.
5. **임시저장** — 지금은 `publish()` 가 곧바로 발행한다. 네이버 임시저장
   버튼을 누르는 경로를 추가한다.

## 4. MCP 도구

발행은 되돌리기 어려우므로 작성과 발행을 분리한다.

```
check_auth()              로그인 세션 확인 (모든 작업 전 최초 호출)
list_categories()         블로그 카테고리 목록
create_draft(html, ...)   HTML 파싱 → 에디터 작성 → 임시저장까지만
publish(draft_id)         명시적 확인 후 발행
get_post / update_post
```

`create_draft` ↔ `publish` 분리가 핵심이다. 임시저장 상태에서 사람이 한 번
보고 발행하는 흐름이 되고, 의도치 않은 글이 나가는 것을 막는다.
`open_type` 기본값은 `private`(비공개)로 유지한다.

## 5. 운영상 주의

- **발행 페이스** — 네이버는 자동 생성 글 대량 발행에 민감하다(저품질 블로그
  판정). 하루 1~2건, 사람이 검수하는 속도가 안전하다.
- **이미지 저작권** — 검색으로 찾은 이미지를 그대로 올리지 않는다. 출처가
  분명한 보도자료·공공데이터, 직접 촬영, 생성 이미지만 쓴다.
- **커밋 금지 대상** — 크롬 프로필(로그인 세션), 네이버 계정 정보.
  `.gitignore` 참고.

## 6. 이미지 소스 (결정)

**글을 쓰는 Claude 가 원본 사이트에서 직접 내려받아 로컬에 저장하고, HTML 에는
그 파일의 절대 경로를 넣는다.** MCP 는 받은 경로를 업로드만 한다.

이유:

- 뉴스·기업 사이트의 hotlink 차단과 User-Agent 검사 때문에, MCP 서버가 나중에
  URL 을 내려받으려 하면 403 이 떨어져 이미지가 통째로 빠진다.
- 네이버는 자사 CDN 에 업로드된 이미지만 본문에 넣으므로 어차피 파일이 필요하다.
- 글을 쓰는 쪽이 이미지를 실제로 보고 내용에 맞는지 판단할 수 있다.

외부 URL 도 `download_image()` 로 폴백 처리하되 권장 경로가 아니다.
지침은 [WRITER_PROMPT.md](WRITER_PROMPT.md) 참고.

  발행 파이프라인이 동작한 뒤 실제 결과물을 보며 다듬는다.
