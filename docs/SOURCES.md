## 1. 주제 선별 — 가장 중요한 판단

소스에서 주제를 고르는 일이 글쓰기보다 중요하다. 아무리 잘 써도 아무도
궁금해하지 않는 주제면 읽히지 않는다.

### 판단 축: 잠재 독자 수 × 검색 의도

같은 IT 뉴스라도 관심의 폭이 100배 차이 난다.

| | 아이폰 18 프로맥스 디자인 유출 | Flutter 4.0 베타 출시 |
|---|---|---|
| 대상을 쓰는 사람 | 수천만 명 | 이 프레임워크를 쓰는 개발자만 |
| 검색할 이유 | 살까 말까 결정을 앞둠 | 이미 쓰는 사람이 릴리스 노트를 봄 |
| 사전지식 | 필요 없음 | 없으면 제목도 이해 안 됨 |
| 감정 반응 | 기대·실망 있음 | 없음 |

### 세 가지 질문

주제를 고르기 전에 스스로 물어본다.

1. **이 뉴스의 주인공을 내 주변 10명 중 몇 명이 쓰나?**
   3명 미만이면 거른다.
2. **제목을 읽고 "그래서 어떻게 되는데?" 소리가 나오나?**
   안 나오면 클릭될 이유가 없다.
3. **전문용어를 풀지 않고도 제목이 이해되나?**
   풀어야 한다면 이미 니치다.

### 등급

**A급 — 바로 쓴다.** 대중이 매일 만지는 물건이 달라지는 소식.

- 아이폰·갤럭시 신제품, 유출, 스펙, 가격
- iOS·안드로이드 업데이트로 **뭐가 달라지는지**
- 카카오톡·네이버·유튜브·넷플릭스 등 국민 서비스의 기능 변화, 요금 인상
- 통신 요금제, 보안 사고·개인정보 유출
- 대중이 쓰는 AI 서비스(ChatGPT 등)의 기능 변화
- 전기차 리콜·가격 인하 (테슬라 등)

**B급 — 각도를 바꾸면 쓴다.** 그대로 옮기면 안 읽히지만 번역하면 살아난다.

- 반도체·부품 기술 → "그래서 내년 내 폰이 얼마나 빨라지나"
- 기업 실적·조직 개편 → "내가 쓰는 이 서비스는 어떻게 되나"
  (예: "애플, 시리·비전프로 인력 200여 명 감원" → 시리 개선은 언제 오나)
- 규제·소송 → "앱 가격이 내려가나"

**C급 — 쓰지 않는다.** 그 도구를 쓰는 사람만 관심 있는 소식.

- 프레임워크·라이브러리 릴리스 (Flutter, React, Rust, Next.js …)
- 개발 도구, DevOps, 클라우드 요금제
- B2B·엔터프라이즈 솔루션
- 학술 논문 그 자체
- 특정 언어·에디터 논쟁

**C급을 A급으로 끌어올릴 수 있는 예외**는 있다. 개발자 얘기라도 "AI가 개발자
일자리를 어떻게 바꾸는가"처럼 **직업·돈·일상**에 걸리면 대중 주제가 된다.
다만 이건 기획이 필요한 일이지, 릴리스 소식을 그대로 옮기는 것과는 다르다.

## 2. 소식 출처

### 해외 — 속도와 유출

| 사이트 | 성격 | 비고 |
|---|---|---|
| [MacRumors](https://www.macrumors.com/) | 애플 루머·유출 | **확인함**: 상단 기사의 60~70%가 루머/유출. A급 주제 밀도가 가장 높다 |
| [9to5Mac](https://9to5mac.com/) | 애플 속보·코드 분석 | 베타 코드에서 미공개 기능을 찾아내는 기사가 많다 |
| [The Verge](https://www.theverge.com/) | 종합 테크 | 하루 30~40건. 대중 눈높이 서술의 교본 |
| [Engadget](https://www.engadget.com/) | 종합·가젯 | 속보가 빠르다 |
| [TechCrunch](https://techcrunch.com/) | 스타트업·투자 | B급이 많다. 대중 주제는 골라내야 |
| [Ars Technica](https://arstechnica.com/) | 심층 분석 | 사실 확인용 참고 자료로 쓰기 좋다 |
| [SamMobile](https://www.sammobile.com/) | 삼성 전용 | 갤럭시 펌웨어·유출 |
| [GSMArena](https://www.gsmarena.com/) | 스마트폰 스펙 | 스펙 비교 사실 확인에 유용 |

**루머는 출처의 신뢰도가 곧 글의 신뢰도다.** 블룸버그 마크 거먼, 디인포메이션
같은 1차 취재원과, 익명 유출 계정을 인용한 2차 보도는 구분해서 써야 한다.
(자세한 표기 방법은 [STYLE.md](STYLE.md) §5)

### 국내

| 사이트 | 성격 | 비고 |
|---|---|---|
| [지디넷코리아](https://zdnet.co.kr/news/) | 종합 IT | **확인함**: AI·기술 혁신 기사가 지배적, 게임·반도체가 뒤따름 |
| [전자신문](https://www.etnews.com/) | 산업·기업 | B급이 많다. 국내 출시·가격 확인용 |
| [ITWorld](https://www.itworld.co.kr/) | 해외 매체 번역 | 실무자 대상. C급 비중 높음 |
| [아이티데일리](https://www.itdaily.kr/) | 기업 IT | 대부분 C급 |

**국내 매체는 주제 발굴보다 "한국 상황 확인"에 쓴다.** 해외에서 터진 소식의
국내 출시일·가격·통신사 대응을 여기서 찾는다. 이게 외신 번역 글과 갈리는
지점이다.

### 개발자 커뮤니티 — 주의

| 사이트 | 성격 |
|---|---|
| [긱뉴스](https://news.hada.io/) | **확인함**: 올라온 글이 거의 전부 개발자 니치 |
| [Hacker News](https://news.ycombinator.com/) | 같은 성격 |

이 두 곳은 **주제 소스로 쓰면 C급만 나온다.** 실제로 확인해 보니 상위 글이
AI 에이전트 관리, 코드 리뷰 속도, Web Audio API 학습 같은 것들이었다. 재미는
있지만 일반 독자는 검색하지 않는 주제다. 기술적 사실을 확인하는 참고용으로만
쓰고, 여기서 주제를 고르지 않는다.

## 3. 주제를 고른 뒤

1. **원본을 찾는다.** 매체 기사가 아니라 그 기사가 인용한 곳(애플 뉴스룸,
   기업 보도자료, 규제 기관 서류)까지 거슬러 올라간다.
2. **출처 2곳 이상에서 교차 확인한다.** 특히 숫자·날짜·모델명.
3. **국내 상황을 덧붙인다.** 한국 출시일, 한국 가격, 국내 통신사·서비스 대응.
   이게 없으면 그냥 번역 글이다.
4. **이미지를 원본 사이트에서 내려받는다.** ([WRITER_PROMPT.md](WRITER_PROMPT.md) §3)
